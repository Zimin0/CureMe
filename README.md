# Капсулка (kapsulka.ru) — домашняя аптечка для всей семьи

Веб-приложение, которое одинаково удобно открывать с компьютера и с телефона (его можно установить на главный экран как приложение).

## Что умеет

- **Семья и аккаунты.** У каждого свой вход. Владелец приглашает родных ссылкой или кодом (`/join/КОД`), либо добавляет по почте. Аптечка общая, а отметки «★ избранное» и «♥ помогает мне» у каждого свои. Можно вести несколько аптечек (например, «Дача»).
- **Лекарства и категории.** Категории общие для всех семей: 12 создаются сразу (обезболивающие, жаропонижающие, аллергия…), менять и добавлять их может администратор, выбирая значок из набора эмодзи и цвет из палитры. Лекарству можно поставить до трёх категорий; первая основная, её значок и цвет видны в списках.
- **Панель администратора** (`/admin`, пункт «Админка» в меню или кнопка на странице «Семья»). Все аккаунты: переименовать, сменить почту, задать новый пароль, выдать или снять права администратора, удалить. Все семьи: переименовать, добавить или убрать участника, назначить владельца, удалить семью с аптечкой. Общий список категорий: добавить, изменить, удалить, поменять порядок. Администратором становится первый зарегистрированный аккаунт; дальше он может выдать права другим.
- **Сроки годности.** У каждой упаковки свой срок. На главной видно просроченное, то, что истекает в ближайшие 30 дней, и то, что заканчивается.
- **Остатки.** Кнопка «Принял(а) N» списывает из упаковки, у которой срок кончается раньше.
- **История приёма.** Каждое «Принял(а)» попадает в историю: кто, когда и сколько. Последние приёмы видны на странице лекарства, вся история семьи — на странице «История приёма» (пункт «История» в меню), с фильтром «только мои». Несколько нажатий одного лекарства одним человеком в пределах минуты (считая от последнего нажатия) складываются в одну запись. Принять можно в одно нажатие, а кнопка 💬 рядом открывает поле для комментария («почему принял»); комментарий можно дописать и позже. Комментарии видит только их автор, остальные члены семьи видят сам приём. Если лекарство удалить, история остаётся; если удалить аккаунт, его история удаляется.
- **Подбор под болезнь.** Ищет по полю «От чего помогает», категориям и названию, понимает синонимы и формы слов («болит голова» находит «головная боль» и «мигрень»). Лекарства с отметкой «помогает мне» идут первыми, закончившиеся и просроченные уходят вниз с предупреждением.
- **Сканирование кода на упаковке камерой.** Читает DataMatrix «Честного знака» и обычный штрихкод EAN-13. Из DataMatrix сразу берутся **срок годности, серия и серийный номер упаковки**, так что одну и ту же коробку нельзя учесть дважды. Если лекарство уже есть, добавляется новая упаковка. Если нет, открывается форма с заполненным кодом и сроком. Незнакомый штрихкод CureMe ищет в интернете (DuckDuckGo, затем Bing): аптеки пишут штрихкод на страницах товаров, и из их заголовков голосованием собираются название, форма, дозировка и число штук в пачке. Например, 4605077018932 → «Ларингобакт таблетки для рассасывания 20 мг + 10 мг №30». Найденное сразу сохраняется в общий справочник, так что второй раз в сеть уже не ходим. Перед сохранением остаток вводится блистерами (сколько осталось × по сколько в блистере) или просто штуками. Проверить поиск с вашего компьютера: `cd backend && python -m app.websearch 4605077018932`. Без камеры можно загрузить фото кода или ввести цифры вручную.

- **Фото лекарства.** Фото упаковки можно добавить при скане, в форме или в карточке. Перед загрузкой оно сжимается в браузере до 1600 px, миниатюры видны в списке.
- **Срок годности по фото или текстом.** Рядом с полем «Годен до» есть кнопки «Сфотографировать срок» и «Ввести текстом». Фото распознаётся прямо в телефоне (tesseract.js, без интернета и сторонних сервисов), из текста достаётся дата: «05.2027», «годен до 31.05.2027», «EXP 05/27», «май 2027». Если на упаковке рядом дата изготовления, берётся более поздняя дата или та, что стоит после «годен/EXP».
- **Напоминания в Telegram и на почту** (Плюс). «Семья» → «Напоминания»: человек выбирает, куда слать (почта, Telegram-бот) и о чём: лекарство заканчивается (порог «Напомнить, когда останется» в форме лекарства), срок годности истекает (за 7–60 дней) или истёк. Раз в день в 10:00 по Москве приходит одно сообщение со всем новым; об одном и том же не повторяем, пока повод не исчезнет (пополнили остаток, выбросили упаковку). После «Принял(а)» семья проверяется сразу. Telegram подключается одноразовой ссылкой `t.me/<бот>?start=<код>` после отдельного согласия на передачу данных; как создать бота — DEPLOY.md, раздел 8.
- **Экспорт.** Кнопка «Экспорт» на странице «Аптечка» выгружает txt-файл: название и дозировка по одной строке, для всей аптечки или только того, что есть в наличии.

## Как запустить

### Для разработки

Нужны **Node.js 20+** (лучше 22, см. `frontend/.nvmrc`) и **Python 3.10+**. Старый Node из `apt` в Ubuntu/WSL (v12) не подойдёт: Vite упадёт с `SyntaxError: Unexpected reserved word`.

```bash
# бэкенд
cd backend
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
alembic upgrade head
uvicorn app.main:app --reload            # http://localhost:8000/docs — документация API

# фронтенд (в другом терминале)
cd frontend
npm install
npm run dev                              # http://localhost:5173, запросы /api уходят на :8000
```

Тесты бэкенда: `cd backend && pytest`. Тесты фронтенда: `cd frontend && npm test`, e2e в браузере: `npm run build && npm run test:e2e`. Все уровни тестов, как их запускать и словарик терминов — в [TESTING.md](TESTING.md).

### Одним контейнером

```bash
CUREME_SECRET_KEY=$(openssl rand -hex 32) docker compose up --build   # http://localhost:8000
```

Поднимаются два контейнера: приложение и PostgreSQL 16 (данные в томе `pg-data`, фото лекарств в томе `cureme-data`). Для разработки без Docker по умолчанию используется файл SQLite, ничего ставить не нужно.

**Переезд с SQLite на Postgres** происходит сам при первом старте: если в томе `/data` лежит старая `cureme.db`, а база Postgres пустая, `start.sh` догоняет обе базы миграциями и одной транзакцией копирует все таблицы (`app/sqlite_import.py`). Потом файл переименовывается в `cureme.db.imported-<время>` и остаётся как резервная копия. Если в Postgres уже есть пользователи, перенос пропускается, так что повторный запуск ничего не сломает.

Как выложить на свой сервер с доменом и HTTPS — пошагово в [DEPLOY.md](DEPLOY.md). Камера в браузере работает только по **HTTPS** (или на `localhost`). Чтобы семья открывала приложение с телефонов, его нужно разместить на сервере с HTTPS-доменом: VPS + Caddy, Railway, Fly.io, Render и т.п.

### Настройки (переменные окружения)

| Переменная | По умолчанию | Что это |
|---|---|---|
| `CUREME_DATABASE_URL` | `sqlite:///./cureme.db` | База. В `docker-compose.yml` это Postgres: `postgresql+psycopg://cureme:…@db:5432/cureme` |
| `CUREME_DB_PASSWORD` | `cureme` | Пароль Postgres в `docker-compose.yml`. На сервере создаётся случайный при первом деплое и хранится в `/opt/cureme/.env` |
| `CUREME_SECRET_KEY` | dev-значение | Ключ подписи токенов входа. **Обязательно поменять** |
| `CUREME_MEDIA_DIR` | `./media` | Папка для фото лекарств (в Docker — `/data/media`) |
| `CUREME_EXPIRING_SOON_DAYS` | `30` | С какого момента срок считается «скоро истекает» |
| `CUREME_ADMIN_EMAILS` | пусто | Почты, которые всегда получают права администратора, в формате JSON: `["me@example.com"]`. Запасной вход, если первый аккаунт потерян |
| `CUREME_SMTP_HOST` | пусто | SMTP-сервер для писем, например `smtp.yandex.ru`. Пока пусто, письма пишутся в лог, а подтверждение почты выключено |
| `CUREME_SMTP_PORT` / `CUREME_SMTP_SECURITY` | `465` / `ssl` | Порт и шифрование: `ssl` для 465, `starttls` для 587 |
| `CUREME_SMTP_USER` / `CUREME_SMTP_PASSWORD` | пусто | Логин и пароль SMTP (у Яндекса — пароль приложения) |
| `CUREME_MAIL_FROM` | = `CUREME_SMTP_USER` | Адрес отправителя |
| `CUREME_PUBLIC_URL` | из запроса | Адрес сайта для ссылок в письмах. На сервере `https://<домен>` |
| `CUREME_EMAIL_VERIFICATION` | авто | Требовать подтверждения почты. По умолчанию включено, только если задан `CUREME_SMTP_HOST` |
| `CUREME_TELEGRAM_BOT_TOKEN` / `CUREME_TELEGRAM_BOT_USERNAME` | пусто | Токен Telegram-бота от @BotFather и его имя без @. Пусто — напоминания только на почту |
| `CUREME_REMINDERS_HOUR` | `10` | В котором часу по Москве рассылать напоминания |
| `CUREME_BACKGROUND_JOBS` | `true` | Фоновые потоки (рассылка напоминаний, Telegram-бот). В тестах выключены |
| `CUREME_REMOTE_LOOKUP` | `true` | Искать незнакомые штрихкоды в интернете (поисковики, затем Open Food Facts) |

## Версии

Номер версии хранится в одном месте — файле [`VERSION`](VERSION) (сейчас `1.0.0`), по правилам SemVer.
Его видно в приложении мелким текстом внизу раздела «Семья» (вместе с коротким коммитом сборки)
и в `GET /api/version`: `{"version": "1.0.0", "commit": "a1b2c3d", "built_at": "2026-09-27T21:00:00Z"}`.
Коммит и время сборки вшивает деплой (`docker build --build-arg CUREME_COMMIT=… CUREME_BUILT_AT=…`).

Как выпустить новую версию:

1. По ходу работы записывайте изменения в раздел «Не выпущено» в [`CHANGELOG.md`](CHANGELOG.md).
2. Перед выпуском: `python scripts/release.py bump patch` (исправления), `minor` (новые возможности)
   или `major` (несовместимые изменения). Скрипт меняет `VERSION`, `frontend/package.json`, `package-lock.json`
   и переносит «Не выпущено» в раздел новой версии с датой.
3. Merge в main: сайт обновится как обычно, а workflow `release.yml` поставит git-тег `vX.Y.Z`
   и создаст GitHub Release с заметками из CHANGELOG.

Тест `scripts/test_release.py` падает, если версии в файлах разошлись или в CHANGELOG нет раздела текущей версии.

## Словарик для собеседования

**REST API** — стиль API, где ресурсы адресуются URL (`/families/3/medicines/7`), а действия задаются HTTP-методами (GET читать, POST создать, PATCH изменить, DELETE удалить). *Зачем:* понятный контракт между фронтендом и бэкендом. *Плюсы:* просто, кешируется, легко тестировать и документировать.

**FastAPI** — Python-фреймворк для API на основе аннотаций типов. *Зачем:* из типов он сам проверяет входные данные и строит документацию `/docs` (OpenAPI). *Плюсы:* мало кода, быстрый (ASGI), встроенная система зависимостей.

**Dependency Injection (Depends)** — функция объявляет, что ей нужно (текущий пользователь, сессия БД, членство в семье), а фреймворк это подставляет. Здесь проверка «пользователь состоит в семье» написана один раз в `deps.py` и переиспользуется во всех маршрутах. *Плюсы:* нет дублирования, легко подменять в тестах (`dependency_overrides`).

**Pydantic** — библиотека валидации данных по типам. *Зачем:* схемы запросов и ответов (`schemas.py`). *Плюсы:* ошибки ввода ловятся на входе, данные сериализуются автоматически.

**ORM (SQLAlchemy)** — отображение таблиц в Python-классы. *Зачем:* работать с БД объектами, а не строками SQL. *Плюсы:* защита от SQL-инъекций, переносимость между SQLite и Postgres, связи (`relationship`) и каскадное удаление.

**Миграции (Alembic)** — версионированные скрипты изменения схемы БД. *Зачем:* обновлять структуру базы, не теряя данные. *Плюсы:* схема под контролем версий, одинаковая у всех окружений.

**JWT** — подписанный токен с id пользователя и сроком действия. Клиент шлёт его в заголовке `Authorization: Bearer …`. *Плюсы:* сервер не хранит сессии (stateless), легко масштабировать. *Минус:* нельзя мгновенно отозвать до истечения срока.

**Хеширование паролей (bcrypt)** — пароль хранится как медленный хеш с солью. *Зачем:* при утечке базы пароли не восстановить. *Плюсы:* соль защищает от радужных таблиц, медленность — от перебора.

**Multi-tenancy (изоляция арендаторов)** — несколько «семей» в одной базе, и каждая видит только своё. Здесь каждый запрос идёт через `family_id` и проверку членства; тест `test_other_family_is_isolated` это проверяет. *Плюсы:* одна установка на всех, при этом данные разделены.

**SPA (React)** — одностраничное приложение: страница загружается один раз, дальше React перерисовывает только нужные части. *Плюсы:* быстрый отклик, ощущается как нативное приложение.

**TypeScript** — JavaScript со статическими типами. *Зачем:* ошибки в полях и пропсах видны при сборке. *Плюсы:* автодополнение, безопасный рефакторинг.

**React Query (TanStack Query)** — кеш серверных данных на клиенте. *Зачем:* загрузка, повторные запросы, обновление после изменений (`invalidateQueries`). *Плюсы:* нет ручного `useEffect + useState` для каждого запроса, данные всегда свежие.

**Vite** — сборщик и dev-сервер для фронтенда. *Плюсы:* мгновенный старт и горячая перезагрузка, быстрая сборка.

**PWA (Progressive Web App)** — сайт с манифестом и Service Worker, который можно установить на телефон. *Плюсы:* иконка на экране, запуск без адресной строки, кеширование для работы при плохой связи, один код для всех платформ.

**Адаптивная вёрстка (mobile-first)** — сначала стили для телефона, затем `@media` для широких экранов. Здесь нижняя панель навигации на телефоне превращается в боковое меню на компьютере. *Плюсы:* один интерфейс на все устройства.

**WebAssembly (WASM)** — бинарный формат, который браузер выполняет почти с нативной скоростью. Здесь так работает распознаватель кодов zxing-cpp. *Плюсы:* тяжёлые вычисления прямо в браузере, без сервера и без интернета.

**GS1 DataMatrix** — квадратный 2D-код со структурированными полями по «идентификаторам применения»: `01` — GTIN товара, `21` — серийный номер, `17` — срок годности (ГГММДД), `10` — серия. Переменные поля разделяются символом GS. **GTIN/EAN-13** — номер товара, последняя цифра контрольная (проверяется в `codes.py`).

**Docker / Docker Compose** — упаковка приложения со всем окружением в образ. Здесь multi-stage сборка: Node собирает фронтенд, а итоговый образ содержит только Python и готовые файлы. *Плюсы:* «работает у меня» = работает везде, образ маленький.

**Журнал событий (event log) и дебаунс записей** — вместо того чтобы хранить только текущий остаток, приложение пишет отдельную строку на каждое действие (таблица `intakes`). *Зачем:* по журналу видно историю и можно строить статистику. Частые повторы в коротком окне склеиваются в одну запись (похоже на debounce в интерфейсах): так случайные двойные нажатия не засоряют историю. *Плюсы:* история не зависит от текущего состояния, а копия названия лекарства в записи (денормализация) сохраняет её даже после удаления лекарства.

**Курсорная пагинация** — следующая страница запрашивается «до такого-то времени» (`?before=…`), а не «пропустить N» (`offset`). *Плюсы:* новые записи сверху не сдвигают страницы и не дают дублей, а запрос по индексу остаётся быстрым на любой глубине.

**Web scraping (парсинг выдачи)** — программа скачивает обычную HTML-страницу и вытаскивает из неё данные регулярными выражениями или HTML-парсером. Здесь так читаются заголовки из поисковой выдачи. *Зачем:* когда у источника нет API. *Плюсы:* бесплатно и без ключей. *Минусы:* ломается, если сайт поменяет вёрстку или начнёт показывать капчу, поэтому поиск сделан «мягким»: любая ошибка просто означает «не нашли».

**Кеширование (cache-aside)** — сначала смотрим в своей базе, и только при промахе идём во внешний источник, а ответ сохраняем. Так устроена таблица `product_codes`. *Плюсы:* быстро, меньше внешних запросов, работает, даже если источник недоступен.

**multipart/form-data** — формат HTTP-запроса для отправки файлов: тело делится на части с границей (boundary), у каждой свои заголовки. В FastAPI файл принимается как `UploadFile`. *Плюсы:* файл передаётся как есть, без раздувания на треть, как у base64 в JSON.

**Проверка файла по сигнатуре (magic bytes)** — тип определяется по первым байтам (`FF D8 FF` — JPEG, `89 50 4E 47` — PNG), а не по расширению или заголовку от клиента, которые легко подделать. Файл сохраняется под случайным именем, так что пути не угадать и чужой файл не перезаписать.

**Content-Disposition** — заголовок ответа, который говорит браузеру «скачай как файл с таким именем». `filename*=UTF-8''…` позволяет кириллицу в имени.

**OCR (оптическое распознавание символов)** — превращение картинки с текстом в строку. Здесь это tesseract.js: движок Tesseract, собранный в WebAssembly, работает в браузере. *Плюсы:* фото не уходит на сервер (приватность), работает офлайн, бесплатно. *Минус:* хуже справляется с бликами и выдавленным текстом, поэтому снимок перед распознаванием переводится в серый и контраст растягивается.

**Ленивая загрузка (code splitting, `import()`)** — тяжёлый код грузится только когда нужен. Движок OCR весит ~7 МБ и скачивается при первом фото срока, а не при открытии приложения. *Плюсы:* быстрый первый запуск.

**Юнит-тесты (Vitest / pytest)** — маленькие быстрые проверки одной функции на наборе примеров. Разбор дат покрыт таблицей случаев («05.2027», «EXP 02/28», дата изготовления рядом). *Плюсы:* ловят регрессии при правках, служат документацией форматов.

**Reverse proxy (Caddy)** — сервер-посредник перед приложением: принимает HTTPS-запросы из интернета и передаёт их приложению внутри. *Зачем:* TLS-сертификаты, сжатие, лимиты, один вход для нескольких сервисов. *Плюсы Caddy:* сам получает и продлевает сертификаты Let's Encrypt, конфиг в 5 строк.

**CORS** — правило браузера, какие чужие сайты могут обращаться к API. Нужен только в разработке, когда фронтенд на :5173, а API на :8000. В продакшене они на одном адресе.

**RBAC (управление доступом по ролям)** — права зависят от роли: администратор приложения (`users.is_admin`), владелец или участник семьи (`memberships.role`). *Зачем:* обычный пользователь видит только свою аптечку, а админ управляет всеми. *Плюсы:* проверка роли живёт в одной зависимости (`admin_user` в `deps.py`), и роутер `/api/admin` целиком закрыт ею через `dependencies=[Depends(admin_user)]`, так что новую ручку нельзя забыть защитить.

**Миграция данных** — миграция, которая меняет не только схему, но и сами записи. Здесь одноимённые категории разных семей слились в одну общую, а лекарства переехали на неё, и только потом удалилась колонка `family_id`. *Плюсы:* обновление на сервере проходит само при деплое (`alembic upgrade head`), ничего не теряется. Проверяется так: накатить на базу со старыми данными и откатить обратно.

**PostgreSQL против SQLite** — SQLite хранит базу в одном файле внутри приложения, Postgres — отдельный сервер базы данных. *Зачем переезжать:* Postgres спокойно выдерживает много одновременных записей (SQLite блокирует файл целиком), строго проверяет типы и длину строк, умеет резервное копирование без остановки (`pg_dump`) и масштабируется. *Плюсы SQLite:* ноль настройки, удобно для разработки и тестов, поэтому тесты гоняются на обеих базах.

**Перенос данных между СУБД** — схема в новой базе создаётся теми же миграциями, а данные копируются таблица за таблицей в порядке внешних ключей (сначала родители: семьи, потом лекарства), одной транзакцией. После вставки с явными id нужно сдвинуть последовательности Postgres (`setval`), иначе следующая запись получит id=1 и упадёт на уникальности ключа.

**Связь «многие ко многим» (many-to-many)** — когда у одной записи может быть несколько связанных, и наоборот: у лекарства до трёх категорий, в категории много лекарств. Хранится через **таблицу связей** (association table) `medicine_categories`: в каждой строке пара `medicine_id` + `category_id` (вместе это первичный ключ, повтор невозможен) и `position` для порядка. *Зачем:* колонка `category_id` в самой таблице лекарств вмещает только одну категорию, а список через запятую в строке нельзя проверить внешним ключом и неудобно фильтровать. *Плюсы:* целостность (удалили категорию, связи удалились сами через `ON DELETE CASCADE`), быстрый фильтр по индексу, в таблицу связей можно добавить свои поля (здесь порядок).

**Обратная совместимость API** — старые клиенты продолжают работать после изменения формата. Здесь поле `category_id` заменили списком `category_ids`, но сервер по-прежнему понимает старое поле (установленное на телефоне приложение может ещё какое-то время работать из кэша).

**Семантическое версионирование (SemVer)** — номер версии `МАЖОРНАЯ.МИНОРНАЯ.ПАТЧ`: патч растёт при исправлениях, минорная — при новых возможностях без поломок, мажорная — когда что-то меняется несовместимо. *Зачем:* по номеру сразу понятно, насколько крупное обновление и безопасно ли его ставить. *Плюсы:* общепринятое соглашение (npm, pip, Docker-теги), удобно сравнивать версии и ссылаться на них в баг-репортах.

**Единый источник правды (single source of truth)** — значение хранится в одном месте, остальные его читают. Здесь это файл `VERSION`: бэкенд читает его при старте, фронтенд — при сборке (`define` в Vite). *Плюсы:* версии не расходятся; а там, где копия неизбежна (package.json), её сверяет тест.

**Git-тег и GitHub Release** — тег закрепляет имя (`v1.0.0`) за конкретным коммитом, релиз добавляет к нему описание изменений. *Зачем:* всегда можно найти и откатиться к коду любой версии. *Плюсы:* история выпусков видна на GitHub, релиз создаётся автоматически из CHANGELOG.

**CHANGELOG** — файл с перечнем изменений по версиям (формат Keep a Changelog: «Добавлено», «Исправлено», «Безопасность»). *Зачем:* пользователям и команде видно, что поменялось, без чтения коммитов. *Плюсы:* ревьюер проверяет его вместе с кодом, из него же собираются заметки к релизу.

**Build-аргументы и метаданные сборки** — `docker build --build-arg` передаёт в образ значения на этапе сборки (здесь коммит и время), а приложение отдаёт их в `/api/version`. *Зачем:* точно знать, какой код сейчас работает на сервере. *Плюсы:* быстрая диагностика («у вас старая сборка?»), не нужно заходить на сервер.

**Фоновая задача (планировщик)** — код, который приложение выполняет само по расписанию, без запроса пользователя. Здесь это поток в том же процессе uvicorn (`reminders.py`): раз в минуту проверяет, не пора ли ежедневной рассылке. *Зачем:* напоминания должны приходить, даже когда сайт никто не открывает. *Плюсы:* не нужен отдельный cron или контейнер; *минус:* при нескольких процессах сервера задача запустится в каждом (у нас процесс один, а повторы гасит таблица отправленных).

**Идемпотентность** — повторное выполнение операции не меняет результат. Рассылка записывает, что уже отправлено (`reminders_sent`), поэтому её можно перезапустить после деплоя без дублей. *Плюсы:* безопасные повторы при сбоях.

**Long polling** — клиент отправляет запрос «есть новое?», а сервер держит его открытым, пока не появятся данные или не пройдёт таймаут (у Telegram — до 50 секунд). Так бот получает сообщения (`getUpdates`). *Альтернатива:* webhook — Telegram сам шлёт запрос на наш адрес. *Плюсы long polling:* не нужен публичный адрес и настройка, работает и локально.

**Deep link** — ссылка, которая открывает приложение сразу в нужном месте с параметром. `t.me/бот?start=код` открывает чат с ботом и передаёт ему код: по нему бот понимает, какой аккаунт привязать. *Плюсы:* человеку не нужно ничего копировать и вводить.
