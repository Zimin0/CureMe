# CureMe — домашняя аптечка для всей семьи

Веб-приложение, которое одинаково удобно открывать с компьютера и с телефона (его можно установить на главный экран как приложение).

## Что умеет

- **Семья и аккаунты.** У каждого свой вход. Владелец приглашает родных ссылкой или кодом (`/join/КОД`), либо добавляет по почте. Аптечка общая, а отметки «★ избранное» и «♥ помогает мне» у каждого свои. Можно вести несколько аптечек (например, «Дача»).
- **Лекарства и категории.** 12 категорий создаются сразу (обезболивающие, жаропонижающие, аллергия…), их можно менять и добавлять свои.
- **Сроки годности.** У каждой упаковки свой срок. На главной видно просроченное, то, что истекает в ближайшие 30 дней, и то, что заканчивается.
- **Остатки.** Кнопка «Принял(а) N» списывает из упаковки, у которой срок кончается раньше. Порог «напомнить, когда останется N» задаётся для каждого лекарства.
- **Подбор под болезнь.** Ищет по полю «От чего помогает», категориям и названию, понимает синонимы и формы слов («болит голова» находит «головная боль» и «мигрень»). Лекарства с отметкой «помогает мне» идут первыми, закончившиеся и просроченные уходят вниз с предупреждением.
- **Сканирование кода на упаковке камерой.** Читает DataMatrix «Честного знака» и обычный штрихкод EAN-13. Из DataMatrix сразу берутся **срок годности, серия и серийный номер упаковки**, так что одну и ту же коробку нельзя учесть дважды. Если лекарство уже есть, добавляется новая упаковка. Если нет, открывается форма с заполненным кодом и сроком. Незнакомый штрихкод CureMe ищет в интернете (DuckDuckGo, затем Bing): аптеки пишут штрихкод на страницах товаров, и из их заголовков голосованием собираются название, форма, дозировка и число штук в пачке. Например, 4605077018932 → «Ларингобакт таблетки для рассасывания 20 мг + 10 мг №30». Найденное сразу сохраняется в общий справочник, так что второй раз в сеть уже не ходим. Перед сохранением остаток вводится блистерами (сколько осталось × по сколько в блистере) или просто штуками. Проверить поиск с вашего компьютера: `cd backend && python -m app.websearch 4605077018932`. Без камеры можно загрузить фото кода или ввести цифры вручную.

- **Фото лекарства.** Фото упаковки можно добавить при скане, в форме или в карточке. Перед загрузкой оно сжимается в браузере до 1600 px, миниатюры видны в списке.
- **Срок годности по фото или текстом.** Рядом с полем «Годен до» есть кнопки «Сфотографировать срок» и «Ввести текстом». Фото распознаётся прямо в телефоне (tesseract.js, без интернета и сторонних сервисов), из текста достаётся дата: «05.2027», «годен до 31.05.2027», «EXP 05/27», «май 2027». Если на упаковке рядом дата изготовления, берётся более поздняя дата или та, что стоит после «годен/EXP».
- **Экспорт.** Вкладка «Экспорт» выгружает txt-файл: название и дозировка по одной строке, для всей аптечки или только того, что есть в наличии.

## Как запустить

### Для разработки

Нужны **Node.js 20+** (лучше 22, см. `frontend/.nvmrc`) и **Python 3.10+**. Старый Node из `apt` в Ubuntu/WSL (v12) не подойдёт: Vite упадёт с `SyntaxError: Unexpected reserved word`.

```bash
# бэкенд
cd backend
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
alembic upgrade head
uvicorn app.main:app --reload            # http://localhost:8000/docs — документация API

# фронтенд (в другом терминале)
cd frontend
npm install
npm run dev                              # http://localhost:5173, запросы /api уходят на :8000
```

Тесты бэкенда: `cd backend && pytest`. Тесты фронтенда: `cd frontend && npm test`, e2e в браузере: `npm run build && npm run test:e2e`. Все уровни тестов, как их запускать и словарик терминов — в [TESTING.md](TESTING.md).

### Одним контейнером

```bash
CUREME_SECRET_KEY=$(openssl rand -hex 32) docker compose up --build   # http://localhost:8000
```

Как выложить на свой сервер с доменом и HTTPS — пошагово в [DEPLOY.md](DEPLOY.md). Камера в браузере работает только по **HTTPS** (или на `localhost`). Чтобы семья открывала приложение с телефонов, его нужно разместить на сервере с HTTPS-доменом: VPS + Caddy, Railway, Fly.io, Render и т.п.

### Настройки (переменные окружения)

| Переменная | По умолчанию | Что это |
|---|---|---|
| `CUREME_DATABASE_URL` | `sqlite:///./cureme.db` | База. Для Postgres: `postgresql+psycopg://user:pass@host/db` |
| `CUREME_SECRET_KEY` | dev-значение | Ключ подписи токенов входа. **Обязательно поменять** |
| `CUREME_MEDIA_DIR` | `./media` | Папка для фото лекарств (в Docker — `/data/media`) |
| `CUREME_EXPIRING_SOON_DAYS` | `30` | С какого момента срок считается «скоро истекает» |
| `CUREME_REMOTE_LOOKUP` | `true` | Искать незнакомые штрихкоды в интернете (поисковики, затем Open Food Facts) |

```

  app/codes.py       разбор GS1 DataMatrix / EAN-13, проверка контрольной цифры
  app/websearch.py   поиск лекарства по штрихкоду через поисковики и разбор заголовков аптек
  app/search.py      подбор по болезни: нормализация, грубый стемминг, синонимы
  alembic/           миграции схемы
  tests/             pytest: unit/ (функции), integration/ (API на настоящей базе), migrations/ (Alembic)
frontend/
  src/pages/         Главная, Аптечка, Карточка, Форма, Скан, Подобрать, Семья, Вход/Регистрация/Приглашение

  src/**/*.test.tsx  Vitest + Testing Library + MSW: функции, компоненты, страницы
  e2e/               Playwright: сценарии в настоящем браузере против настоящего бэкенда
```

## Словарик для собеседования

**REST API** — стиль API, где ресурсы адресуются URL (`/families/3/medicines/7`), а действия задаются HTTP-методами (GET читать, POST создать, PATCH изменить, DELETE удалить). *Зачем:* понятный контракт между фронтендом и бэкендом. *Плюсы:* просто, кешируется, легко тестировать и документировать.

**FastAPI** — Python-фреймворк для API на основе аннотаций типов. *Зачем:* из типов он сам проверяет входные данные и строит документацию `/docs` (OpenAPI). *Плюсы:* мало кода, быстрый (ASGI), встроенная система зависимостей.

**Dependency Injection (Depends)** — функция объявляет, что ей нужно (текущий пользователь, сессия БД, членство в семье), а фреймворк это подставляет. Здесь проверка «пользователь состоит в семье» написана один раз в `deps.py` и переиспользуется во всех маршрутах. *Плюсы:* нет дублирования, легко подменять в тестах (`dependency_overrides`).

**Pydantic** — библиотека валидации данных по типам. *Зачем:* схемы запросов и ответов (`schemas.py`). *Плюсы:* ошибки ввода ловятся на входе, данные сериализуются автоматически.

**ORM (SQLAlchemy)** — отображение таблиц в Python-классы. *Зачем:* работать с БД объектами, а не строками SQL. *Плюсы:* защита от SQL-инъекций, переносимость между SQLite и Postgres, связи (`relationship`) и каскадное удаление.

**Миграции (Alembic)** — версионированные скрипты изменения схемы БД. *Зачем:* обновлять структуру базы, не теряя данные. *Плюсы:* схема под контролем версий, одинаковая у всех окружений.

**JWT** — подписанный токен с id пользователя и сроком действия. Клиент шлёт его в заголовке `Authorization: Bearer …`. *Плюсы:* сервер не хранит сессии (stateless), легко масштабировать. *Минус:* нельзя мгновенно отозвать до истечения срока.

**Хеширование паролей (bcrypt)** — пароль хранится как медленный хеш с солью. *Зачем:* при утечке базы пароли не восстановить. *Плюсы:* соль защищает от радужных таблиц, медленность — от перебора.

**Multi-tenancy (изоляция арендаторов)** — несколько «семей» в одной базе, и каждая видит только своё. Здесь каждый запрос идёт через `family_id` и проверку членства; тест `test_other_family_is_isolated` это проверяет. *Плюсы:* одна установка на всех, при этом данные разделены.

**SPA (React)** — одностраничное приложение: страница загружается один раз, дальше React перерисовывает только нужные части. *Плюсы:* быстрый отклик, ощущается как нативное приложение.

**TypeScript** — JavaScript со статическими типами. *Зачем:* ошибки в полях и пропсах видны при сборке. *Плюсы:* автодополнение, безопасный рефакторинг.

**React Query (TanStack Query)** — кеш серверных данных на клиенте. *Зачем:* загрузка, повторные запросы, обновление после изменений (`invalidateQueries`). *Плюсы:* нет ручного `useEffect + useState` для каждого запроса, данные всегда свежие.

**Vite** — сборщик и dev-сервер для фронтенда. *Плюсы:* мгновенный старт и горячая перезагрузка, быстрая сборка.

**PWA (Progressive Web App)** — сайт с манифестом и Service Worker, который можно установить на телефон. *Плюсы:* иконка на экране, запуск без адресной строки, кеширование для работы при плохой связи, один код для всех платформ.

**Адаптивная вёрстка (mobile-first)** — сначала стили для телефона, затем `@media` для широких экранов. Здесь нижняя панель навигации на телефоне превращается в боковое меню на компьютере. *Плюсы:* один интерфейс на все устройства.

**WebAssembly (WASM)** — бинарный формат, который браузер выполняет почти с нативной скоростью. Здесь так работает распознаватель кодов zxing-cpp. *Плюсы:* тяжёлые вычисления прямо в браузере, без сервера и без интернета.

**GS1 DataMatrix** — квадратный 2D-код со структурированными полями по «идентификаторам применения»: `01` — GTIN товара, `21` — серийный номер, `17` — срок годности (ГГММДД), `10` — серия. Переменные поля разделяются символом GS. **GTIN/EAN-13** — номер товара, последняя цифра контрольная (проверяется в `codes.py`).

**Docker / Docker Compose** — упаковка приложения со всем окружением в образ. Здесь multi-stage сборка: Node собирает фронтенд, а итоговый образ содержит только Python и готовые файлы. *Плюсы:* «работает у меня» = работает везде, образ маленький.

**Web scraping (парсинг выдачи)** — программа скачивает обычную HTML-страницу и вытаскивает из неё данные регулярными выражениями или HTML-парсером. Здесь так читаются заголовки из поисковой выдачи. *Зачем:* когда у источника нет API. *Плюсы:* бесплатно и без ключей. *Минусы:* ломается, если сайт поменяет вёрстку или начнёт показывать капчу, поэтому поиск сделан «мягким»: любая ошибка просто означает «не нашли».

**Кеширование (cache-aside)** — сначала смотрим в своей базе, и только при промахе идём во внешний источник, а ответ сохраняем. Так устроена таблица `product_codes`. *Плюсы:* быстро, меньше внешних запросов, работает, даже если источник недоступен.

**multipart/form-data** — формат HTTP-запроса для отправки файлов: тело делится на части с границей (boundary), у каждой свои заголовки. В FastAPI файл принимается как `UploadFile`. *Плюсы:* файл передаётся как есть, без раздувания на треть, как у base64 в JSON.

**Проверка файла по сигнатуре (magic bytes)** — тип определяется по первым байтам (`FF D8 FF` — JPEG, `89 50 4E 47` — PNG), а не по расширению или заголовку от клиента, которые легко подделать. Файл сохраняется под случайным именем, так что пути не угадать и чужой файл не перезаписать.

**Content-Disposition** — заголовок ответа, который говорит браузеру «скачай как файл с таким именем». `filename*=UTF-8''…` позволяет кириллицу в имени.

**OCR (оптическое распознавание символов)** — превращение картинки с текстом в строку. Здесь это tesseract.js: движок Tesseract, собранный в WebAssembly, работает в браузере. *Плюсы:* фото не уходит на сервер (приватность), работает офлайн, бесплатно. *Минус:* хуже справляется с бликами и выдавленным текстом, поэтому снимок перед распознаванием переводится в серый и контраст растягивается.

**Ленивая загрузка (code splitting, `import()`)** — тяжёлый код грузится только когда нужен. Движок OCR весит ~7 МБ и скачивается при первом фото срока, а не при открытии приложения. *Плюсы:* быстрый первый запуск.

**Юнит-тесты (Vitest / pytest)** — маленькие быстрые проверки одной функции на наборе примеров. Разбор дат покрыт таблицей случаев («05.2027», «EXP 02/28», дата изготовления рядом). *Плюсы:* ловят регрессии при правках, служат документацией форматов.

**Reverse proxy (Caddy)** — сервер-посредник перед приложением: принимает HTTPS-запросы из интернета и передаёт их приложению внутри. *Зачем:* TLS-сертификаты, сжатие, лимиты, один вход для нескольких сервисов. *Плюсы Caddy:* сам получает и продлевает сертификаты Let's Encrypt, конфиг в 5 строк.

**CORS** — правило браузера, какие чужие сайты могут обращаться к API. Нужен только в разработке, когда фронтенд на :5173, а API на :8000. В продакшене они на одном адресе.
