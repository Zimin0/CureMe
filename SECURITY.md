## Что нужно сделать руками

Сервер: `ssh root@158.255.7.113`. Перед изменениями SSH откройте веб-консоль сервера в панели HOSTKEY:
через неё можно войти, даже если SSH перестанет пускать.

1. **Сменить пароль root** (он был виден в чате): `passwd`.
2. **Сменить свой пароль в Капсулке** (он был в чате): Админка → Пользователи → вы → новый пароль.
   После этого все старые входы перестанут действовать, войдите заново.
3. **Запретить вход по паролю в SSH.** Сначала в новом окне проверьте, что `ssh root@158.255.7.113` пускает без пароля. Затем:
   ```bash
   cat > /etc/ssh/sshd_config.d/00-hardening.conf <<'EOF'
   PasswordAuthentication no
   KbdInteractiveAuthentication no
   PermitRootLogin prohibit-password
   MaxAuthTries 3
   EOF
   sshd -t && systemctl reload ssh
   sshd -T | grep -Ei '^(passwordauthentication|permitrootlogin|kbdinteractive)'
   ```
   Откат из веб-консоли HOSTKEY: `rm /etc/ssh/sshd_config.d/00-hardening.conf && systemctl reload ssh`.
4. **Файрвол и защита от перебора SSH:**
   ```bash
   ufw default deny incoming && ufw default allow outgoing
   ufw allow 22/tcp && ufw allow 80/tcp && ufw allow 443/tcp && ufw allow 443/udp
   ufw --force enable && ufw status verbose
   apt update && apt install -y fail2ban unattended-upgrades
   ss -tlnp   # снаружи должны слушать только 22, 80, 443
   ```
   Откат из веб-консоли: `ufw disable`.
5. **Ежедневная копия базы** (14 дней истории):
   ```bash
   cat > /etc/cron.d/cureme-backup <<'EOF'
   30 3 * * * root cd /opt/cureme && mkdir -p backups && docker compose exec -T db pg_dump -U cureme cureme | gzip > backups/db-$(date +\%F).sql.gz && find backups -name 'db-*.sql.gz' -mtime +14 -delete
   EOF
   ```
   Время от времени скачивайте копию к себе: `scp root@158.255.7.113:/opt/cureme/backups/db-*.sql.gz .`
6. **Заменить ключ деплоя**, потому что он лежал открытым текстом в Variables:
   ```bash
   # на своём компьютере (WSL)
   ssh-keygen -t ed25519 -f ~/.ssh/cureme_deploy2 -N "" -C github-actions
   ssh-copy-id -i ~/.ssh/cureme_deploy2.pub root@158.255.7.113
   cat ~/.ssh/cureme_deploy2   # → новый секрет SSH_PRIVATE_KEY
   ```
   Вставьте его в GitHub вместо старого, запустите Actions → Deploy → Run workflow и, когда деплой пройдёт,
   уберите старый ключ с сервера (копия файла остаётся в `authorized_keys.bak`):
   ```bash
   OLD=$(cut -d' ' -f2 ~/.ssh/cureme_deploy.pub)
   ssh root@158.255.7.113 "cp ~/.ssh/authorized_keys ~/.ssh/authorized_keys.bak && grep -vF '$OLD' ~/.ssh/authorized_keys.bak > ~/.ssh/authorized_keys"
   ```
7. **GitHub:** удалите `SSH_PRIVATE_KEY` и `SSH_KNOWN_HOSTS` из Settings → Secrets and variables → Actions → **Variables**
   (в **Secrets** они должны остаться). Включите двухфакторный вход в GitHub, HOSTKEY и REG.RU.
8. **Защита ветки main:** Settings → Branches → Add rule → `main` → Require status checks: `backend (sqlite)`,
   `backend (postgres)`, `frontend`, `e2e`, `docker smoke`. Каждый push в main сразу уходит на сервер,
   так что сломанный код не должен туда попадать.

## Что остаётся (известные риски)

- **Почта подтверждается, только когда настроен SMTP** (DEPLOY.md, раздел 7). После этого новые аккаунты
  попадают в аптечку лишь по ссылке из письма, а права по `CUREME_ADMIN_EMAILS` даются только подтвердившим почту.
  Пока SMTP не настроен, можно зарегистрироваться с чужой почтой: не задавайте `CUREME_ADMIN_EMAILS` для почты,
  у которой ещё нет аккаунта. Аккаунты, созданные до появления проверки, считаются подтверждёнными.
- **Общий справочник штрихкодов** пополняют все семьи. Кто-то может записать неверное название для кода,
  и его увидят другие при сканировании. Это подсказка, человек подтверждает её сам, но полагаться на неё нельзя.
- **Фото лекарств доступны по прямой ссылке** без входа. Ссылка случайная (128 бит), угадать нельзя, но ею можно поделиться.
- **Токен хранится в localStorage** и живёт 30 дней. Украсть его может только скрипт на странице, от этого защищает CSP.
- **Счётчики лимитов в памяти процесса.** Если запустить несколько процессов приложения, нужен общий счётчик (Redis).

## Словарик

- **Rate limiting** (ограничение частоты) — не больше N запросов за окно времени. Зачем: перебор паролей
  и угадывание кодов становятся бесполезными. Плюсы: дёшево, не мешает людям. Ответ `429 Too Many Requests` + `Retry-After`.
- **JWT** (JSON Web Token) — подписанная сервером строка «кто вы и до какого времени». Плюсы: серверу не нужно хранить сессии.
  Минус: его нельзя «отозвать», поэтому добавлена версия токена (`tv`), которая растёт при смене пароля.
- **bcrypt** — намеренно медленная функция хеширования паролей с солью. Плюс: даже утёкшую базу долго перебирать.
  Ограничение: учитывает только первые 72 байта пароля.
- **Timing attack / перечисление пользователей** — узнать секрет по времени ответа. Защита: одинаковая работа в обоих случаях.
- **XSS** (межсайтовый скриптинг) — чужой JavaScript выполняется на вашем сайте и крадёт данные.
- **CSP** (Content Security Policy) — заголовок со списком, откуда браузеру можно грузить скрипты, картинки и т. п.
  Плюс: даже внедрённый `<script>` не запустится.
- **Clickjacking** — сайт прячут в невидимый iframe и заставляют нажать кнопку. Защита: `X-Frame-Options` / `frame-ancestors`.
- **HSTS** (HTTP Strict Transport Security) — браузер запоминает, что на сайт можно только по HTTPS. Защищает от подмены в чужом Wi-Fi.
- **Принцип наименьших привилегий** — каждой части системы ровно те права, что нужны: приложение не root, CI только читает код.
- **fail2ban** — банит адреса, которые много раз ошиблись с паролем SSH.
- **ufw** (Uncomplicated Firewall) — простой файрвол Ubuntu: закрывает все порты, кроме разрешённых.
  Нюанс: Docker открывает опубликованные порты мимо ufw, поэтому в compose наружу опубликованы только 80 и 443.
